# RFC 2119 Normative Keywords

Use RFC 2119 keywords only in documents that impose requirements on
implementations or behaviors: specs, API contracts, protocol docs, READMEs that
define required behavior, and docstrings for public APIs or interfaces. In
tutorials, changelogs, or casual prose they read as emphasis rather than
requirements, so leave them out.

- **Capitalize the full keyword** when using it in the RFC 2119 sense.
  Lowercase `must`, `should`, `may` is plain English with no normative weight.
- **Use them sparingly**: only where interoperation requires it or to limit
  harmful behavior, not to impose implementation choices. Overuse dilutes them.
- **In a formal spec**, include the standard RFC 2119 boilerplate near the top
  so the interpretation is explicit.
